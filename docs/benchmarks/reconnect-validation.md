分区 5 个阶段 PASS，82 份快照的节点身份、无多数派时提交/应用索引冻结、跨分区边不转发数据、恢复后收敛已重新核验。两个故障窗口约 4.293 和 4.087 秒；重连拒绝合计 11 次，低于设定的 100 次保护阈值。三个节点均只启动一次，最终 -15 为测试清理。

最终 Leader 为 2，任期 30，三个节点 commit_index=last_applied=9，待处理提案及应用滞后为 0。4 个探测请求为 2 次明确拒绝、2 次结果未知，没有无多数派时的成功确认。`no-quorum-2` 在恢复后被应用，其他探测键不存在；结果未知允许之后提交，并非错误，也不能改记为已收到成功回复。

## 与旧版同类分区基线比较

| 指标 | 旧版 `9cfcfd6` | 新版 `ef17ef7` | 本次观察 |
| --- | ---: | ---: | --- |
| 转发器拒绝重连总数 | 24,731 | 11 | 减少约 99.96% |
| 完整三节点日志，含清理 | 5,498,325 字节 | 146,110 字节 | 减少约 97.34% |
| 两次实际隔离窗口 | 4.322 / 4.032 秒 | 4.293 / 4.087 秒 | 时间接近但不完全相同 |
| 整轮测试耗时 | 9.593 秒 | 12.929 秒 | 不能当成故障恢复延迟 |

旧版来自[已核验分区证据](partition-validation.md)，没有使用不同负载的过载组 7,897 次作直接基线。新版完整日志分别为 50,456、50,099、45,555 字节；报告 `reconnect_check` 的结束前快照合计 146,022 字节，比包含清理的完整日志少 88 字节。上述日志降幅使用两边完整文件大小，口径一致。

两个版本的初始 Leader 分别为 0 和 1，选举与调度时序不同，这是单次同类场景前后对比，不是严格多轮随机实验。恢复通信到脚本收敛快照的新版间隔约 1.495 和 2.228 秒，包含选举、标记写入和核验，不是仅 TCP 重连延迟。退避在限制重连开销的同时可能延长恢复等待；本次没有 CPU、正常业务 QPS、长期资源或大规模集群的收益证据。

## 复核

```sh
python docs/benchmarks/verify_reconnect_validation.py
```

需要 Python 标准库、相关 Git 历史和仓库内基线证据，不启动服务。脚本检查原始包和文件哈希、源码及二进制记录、CTest 日志、冒烟与分区结果，并从原始文件重新计算对比指标。它不能替代未记录的原始逐次 GET 回复或独立正确性证明。实现和取舍见[优化记录](../optimizations/peer-reconnect-backoff.md)。
