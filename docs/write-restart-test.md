# 第二组故障测试：持续写入期间退出与重启

用户回传的真实 Linux 原始证据已核验，**5 个阶段全部 PASS**；1,704 个已确认键在两次恢复后的三个副本检查中全部保留，见[第二组核验报告](benchmarks/write-restart-validation.md)。第一组 TCP 分区验收也已完成，见[分区报告](benchmarks/partition-validation.md)。

## 本组验收

1. 启动独立三节点集群，一个写入线程每批发送 8 个唯一键；故障前持续写入至少 2 秒，收到至少 64 个成功确认。
2. 向当前 Leader 完成一批请求的 sendall 后、读取该批回复前发送 SIGKILL，记录该批序号、发送和退出时刻。客户端侧有未读取回复的请求，不声称服务端还没有提交它们。
3. 写入线程始终继续尝试新键，按 MOVED 响应或连接失败切换目标；其余两节点选主后，继续写入至少 2 秒并额外确认至少 64 个键。
4. 使用原来配套的 KV / Raft 日志目录重启旧 Leader，再持续写入至少 2 秒并额外确认至少 64 个键。停止写入后，由当前 Leader 确认一个独立的核验标记，等待所有副本应用到该位置，再逐键核对；该标记不计入持续写入的请求数量。
5. 在停止写入之后强制退出全部节点，再从各自原目录重启，重复逐键核对，检查已确认数据和未知请求的最终状态保持一致。这是额外的进程崩溃恢复检查，不模拟整机掉电。

每批结束间隔约 10 ms，最多 20,000 次尝试，默认整轮期限 120 秒；退出清理有额外的有界等待。这是有限负载的可靠性检查，不作为 QPS 或长时间稳定性基准。

## 请求账本与判定

每个键只尝试一次，不在故障后重试同一个键。report.json 的 attempts 保存序号、键、值、目标节点、时刻和结果：

| 结果 | 判定与恢复检查 |
| --- | --- |
| acknowledged | 客户端解析到 OK；恢复后每个副本必须保留精确值 |
| unknown | 发送开始后超时、断连、部分发送失败，或服务返回 leadership lost/server stopped 的 outcome unknown；允许存在或不存在，但副本必须一致且值正确 |
| rejected | 明确的 MOVED 或 BUSY；对应唯一键不应存在 |
| not_sent | 建立连接等发送前步骤失败；对应唯一键不应存在 |

流水线收到部分 OK 后断连，已经解析的成功回复仍计入已确认，其余保留为未知。错误格式、错误值、缺失已确认数据、副本不一致或恢复前后结果变化都会使测试失败。未知不能当成失败，也不能计入成功。

## Ubuntu 执行

更新到包含脚本的版本后，在项目根目录执行：

```bash
python3 tests/cluster_write_restart.py \
  --build-report build-linux-fresh-1vukPy/reports/run-a3q01rgw/build-report.json \
  --artifacts build-linux-fresh-1vukPy/write-restart-reports
```

没有修改 C++ 服务，可复用已验证的全量构建产物；脚本复用构建身份核对逻辑，运行前检查二进制及编译输入与指定报告一致，结束时再次检查代码和二进制指纹。其他机器须填写自己的构建报告路径。

成功时显示 `PASS: real Linux continuous-write restart test; report: .../report.json`。失败则为 FAIL、非零退出码，并保留诊断信息。无需 sudo；仅使用测试自己分配的端口、临时数据目录和子进程。

保存整个报告目录：其中有 report.json、三个节点日志、Git 提交与状态，以及 referenced-build-report.json。原始报告包含逐请求账本、故障和重启时序、阶段确认数量、两次逐键验证摘要、节点生命周期和身份记录。

## 本地辅助验证与边界

```sh
python tests/cluster_write_restart_tests.py
```

8 项辅助检查覆盖流水线部分回复、EOF、连接/发送失败、MOVED、领导权丢失的未知结果、非法回复、恢复判定和写入线程的故障顺序及唯一键约束。辅助测试通过不代表真实 Raft 服务已通过本组验收。

本组是三进程同机的有限场景；SIGKILL 不等同于断电，既有 GET 仍是本地读，存储设备故障与资源长期增长留在各自边界内。本组已通过并归档，收尾仅剩第三组“过载与持续运行”，其中还要关注第一组发现的重连和日志量。
